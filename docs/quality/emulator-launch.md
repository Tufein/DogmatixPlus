# Emulator launch verification for 2.4.0

Play uses a read-only dependency plan independent of the deletion plan. A CUE/GDI/M3U and its local game dependencies remain launchable when another descriptor references them. Removal continues to protect shared files. References use an explicit ROM/disc/audio format allowlist rather than the library scanner's permissive handling of unknown extensions. Saves, unknown configuration/key formats and paths outside the selected folder receive no grants. Relative paths through subfolders require the emulator's own library setup. Recognized formats can be ambiguous (for example `.md` also denotes Markdown); an emulator receives the selected local game files rather than a grant to the whole folder.

The chooser offers descriptor/playlist entry files ahead of their tracks. Audio, subchannel and raw track dependencies receive read grants but are not offered as separate games. Standalone BIN/IMG and Mega Drive MD ROMs remain playable; an extracted entry is preferred over a remaining archive. This selection runs separately per physical folder, so a sheet in one copy cannot hide a standalone ROM in another.

Each installed emulator flavour has its own package-bound preference. Installing Gold, Nightly or another RetroArch build does not change an explicit choice. Earlier package-free catalogue preferences keep preferred-first behaviour; preferences stored as Android components continue to select the same package. Automatic selection intentionally follows the current preferred installed flavour.

The JVM regressions cover dependency closure, shared-file preservation, unrelated broken descriptors, safe references, stable variant preferences, older preferences and PC Engine CD archive handling. The Android regression launches a Java receiver in the test APK's separate UID using the production intent converter. It checks file and track read grants, denial of an unselected sibling save, URI extras and archive MIME handler discovery. The separate process contains no Kotlin runtime dependency.

Catalogue contracts were checked against [ES-DE's Android system configuration](https://gitlab.com/es-de/emulationstation-de/-/raw/master/resources/systems/android/es_systems.xml) and [activity/package rules](https://gitlab.com/es-de/emulationstation-de/-/raw/master/resources/systems/android/es_find_rules.xml). WatermelonDS uses its documented preferred data URI contract, including the Nightly package, from [the project's frontend integration documentation](https://github.com/SapphireRhodonite/WatermelonDS#integration-with-third-party-frontends).

These tests establish Android intent/grant correctness; they do not certify every external emulator build. BIOS/keys, installed RetroArch cores, emulator permissions and save-folder setup remain the emulator's responsibility. A successful Android activity start does not prove that the external app loaded the game. Path-based recipes require a real external-storage path and any access the emulator itself needs. Archives for disc systems require extraction before Play.
