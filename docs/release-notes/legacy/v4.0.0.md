**Dogmatix+ 4.0.0** — whole console sets in one go, downloads that look after themselves, importing a list of games, and a tidier app. Everything since 3.0.0 is in this release.

### Big batches
- **Download all takes a whole console set**: up to 3000 games per tap. The dialog shows the number of games and the space they need first.
- **No more "app isn't responding"** during or after a big batch, and after a restart with hundreds of downloads waiting. Each finished download is handled once, and the Downloads list loads its details in batches in the background.
- **Hold the queue** (*Downloads → Hold the queue*): running downloads finish, nothing new starts until you resume it. The hold stays after a restart.
- **Time left**: the line above the Downloads list shows how much is still to fetch and roughly how long that takes.
- **Whole-queue buttons**: *Stop all*, *Retry failed* and *Clear finished*, each with the number of downloads it acts on.

### Downloads that look after themselves
- **Failed downloads retry by themselves** after 1, 5 and 15 minutes when the connection dropped, timed out or the server was busy (*Settings*, on by default). A missing (404) or refused (403) file is not retried.
- **Pause web downloads**, running or waiting; *Resume* continues from what was already downloaded.
- **Checked against your DAT** after the download when the source publishes no checksum: the row says *✓ matches the DAT* or *not in the DAT*.
- **A notification when the queue is done**, with how many went through and how many failed.

### New in 4.0
- **Import a list** (*Tools → Import a list*): a text file or the clipboard, one game per line (numbering and bullets are fine). Pick a console or look in all of them. The best version of each listed game, by your languages, is downloaded in one go; games you already have are skipped, and the ones no source lists can go on the wishlist.
- **The DAT check finds your missing games**: *Look for them in your sources* hands the missing games of a console to *Import a list*.
- **Recent searches** show under the search field while it is empty; a tap searches again.
- **Surprise me** (next to *Download all*) opens a random game from the list on screen.
- **Text size** (*Settings → Look and controls*): 85 to 150 %, on top of Android's own font size.
- **Faster lookups** in a big library: the file name now has an index in the database.

### Library and frontends
- **Covers for Pegasus and RetroArch** after a download, next to the ones for ES-DE. Covers that are already there are never replaced.
- **The wishlist knows what you already have**: a game on the device or on your RomM server is marked and not downloaded again. **Share the wishlist** as a small file.
- **Move the library** to another storage (*Tools → Storage*): every game is copied, checked, and only then removed from the old place.
- **Frontend check** (*Tools*): what is ready, still to do or manual for ES-DE, iiSU, Daijishō, Pegasus and RetroArch.

### RomM and saves
- **Upload what the server lacks**: sends the finished downloads RomM does not list yet.
- **Save sync for standalone emulators**: DraStic, melonDS, mGBA, Pizza Boy GBA / GBC, GBA.emu, GBC.emu, Snes9x EX+, NES.emu and MD.emu sync their in-game saves with RomM, next to RetroArch.

### A tidier app
- **Settings in groups** (look and controls, downloads, when to download, after a download, torrents and debrid, library, frontends, RomM and saves, profiles, backup, app), with *Tools* as the first row; in portrait LB / RB jump between groups.
- **Tools in groups** too (library, games and checks, frontends, export).
- **What's new**: after an update the highlights of the new version are shown once.
- Under the hood the code was cleaned up: clearer names, imports instead of long package names, and one test file per subject.

### Good to know
- Updating from 3.0.0 keeps everything. The database gets one index (version 12); the first start after the update can take a moment longer in a big library.
- A profile PIN set in 3.0.0 keeps working; new PINs are stored more safely.
- Checked by the unit tests and a debug build in CI. **Not tried on a real device or against a real RomM server yet.** *Move the library* and *Upload what the server lacks* touch your files, so try them on a small folder first. If a big batch still stalls, a diagnostics report (*Settings → Diagnostics*) helps.
